## 1. The challenge in plain words

### What we are building
An indoor Google Maps you can talk to. You ask "where is the coffee machine?", "how do I get to the lift
without stairs?", "the east lift is closed, what changes?", "add a door between 2.03 and 2.04", and the system
answers, shows the route on a floor plan, and keeps the building up to date. It must work for any building in
the organizers' file format, including one we have never seen.

### What the organizers gave us (the kit)
| Folder / file | What it is | Who uses it |
|---|---|---|
| `data/` | 280 buildings. Each has `building.json` (rooms as polygons, doors, stairs, lifts, furniture and machines), one drawn floor plan image per floor (`floor_0.png`, `floor_0_plain.png`), `equipment.csv`, and question files. | everyone |
| `starter_agent/` | A **working prototype**. You type questions in the terminal, Claude answers using six tools (search, route, close, add door, overview, draw). It already does find and route, step-free, closures, multi-stop tours, stairs and lifts. It cannot do areas, door widths, reachability counts, shared walls or stacking, so it scores under 5% on the scored questions. **We extend it, we do not replace it.** | Core, Agent |
| `benchmark/score.py` | The exact scorer the judges use. | Agent, Core |
| `benchmark/evaluate.py` | Runs an agent on every question, scores it, writes the submission CSV. Slow (one question at a time). | Agent |
| `README.md` | The rules. Section 3 is the data format, section 4 the questions, section 6 the scoring. | everyone |

Where the buildings come from (none of them is the Tacto office or Munich Urban Colab):
- **Swiss Dwellings** (109): real Swiss apartment buildings from a public research dataset. Real walls and door widths.
- **ResPlan** (105): real single-floor homes from a public floor plan dataset.
- **OpenStreetMap Munich** (17): real Munich buildings mapped indoors: TUM buildings, Airport Terminal 2, Pasing Arcaden.
- **Procedural** (49): invented factories and campus buildings generated by a program. The only ones with machines and halls.
Furniture and machines are mostly placed by rules, even inside the real buildings.

### What "agent" means here, and why half the work is maths
Claude is the agent: it understands a vague question, asks back when needed, picks the right tool with the
right room and floor, and explains the result in human words. The tools behind it do the exact calculations,
because a language model is bad at arithmetic and the judges want exact numbers. The README says it in one
line: *the agent is the interaction layer, the core underneath is deterministic.* Nothing is trained. "Train"
and "dev" are just buildings **with answers** so we can check our calculations; "test" is buildings
**without answers** that we submit.

### How the 100 points are earned
| Part | Points | What decides it |
|---|---|---|
| Does it work | **55** | Our answers to the 145 test questions, the Sunday surprise building run by one command, and automatic checks on levels 1–4 (incl. buildings built from plans). |
| Interaction | 25 | A scripted chat with tricky users: asks only what it needs, says what it understood, gives directions a person can follow. Voice counts. |
| Creativity | 10 | One extra feature done well. |
| Demo | 10 | Video + one-page technical explanation. |

### The 145 scored questions
| Kind | Test Qs | In plain words | How we compute it | Status |
|---|---|---|---|---|
| `floor_area_total` | 33 | "Total area of all offices on floor 1?" | sum of polygon areas of spaces with that floor and `room_type` | **verified 181/181** on train+dev |
| `shared_walls_count` | 26 | "How many rooms share a wall with Office 0.33?" | rooms on the same floor whose outline runs ≥ 1 m within 0.35 m of ours; corridors, stairwells, lifts excluded | shapely; calibrate on 143 examples |
| `largest_room` | 21 | "Largest meeting room on the ground floor and its area?" | max polygon area among spaces with that floor and `room_type` | **verified 96/96** |
| `errand` | 20 | "From room A, fetch the nearest X, carry it to the largest Y on floor N. Total distance?" | route(A → nearest room holding an X, by route length) + route(→ largest Y). The start room never holds the X. "I can carry it on the stairs" = stairs allowed | reuses starter router; validate on 74 examples |
| `wide_delivery_count` | 18 | "A 1.1 m trolley comes in at the lobby, no stairs. How many rooms on floor 2 can it reach?" | walk from start through doors that are `step_free` and `width_m ≥ 1.1`, and through lifts; count reached spaces with `type == "room"` on that floor (start counts if it is a room) | **verified 80/80** |
| `straight_line_3d` | 15 | "Straight-line distance between the centres of Lab 0.12 and Office 3.07?" | 3D distance between polygon **centroids** at each floor's `elevation_m` | **verified 30/30** |
| `room_stacked` | 9 | "Water drips from the ceiling of 0.29. Which room is above?" | the space on the floor above/below whose outline overlaps ours most. Can be a hall. Only procedural + OSM buildings | shapely; calibrate on 26 examples |
| `what_if_door` | 3 | "Add a door between X and Y. How many rooms on floor 3 get a shorter way out by > 1 m?" | add a door at the midpoint of the shared wall, recompute each room's shortest path to the exit before/after, count improvements > 1 m | shapely; only 4 examples |

87 of 145 are pure arithmetic over the JSON. Everything else reuses the starter's route graph, which already
matches the warm-up answers to the centimetre.

### Answer format rules (everyone memorises these)
- Only the **last** line that starts with `Answer:` is scored.
- Numeric answers: that line holds **exactly one number**. `Answer: 214.7` ✅ · `Answer: 214.7 m²` ✅ (² is not a digit) · `Answer: 214.7 m2` ❌ · `Answer: 214,7` ❌ · `Answer: about 215 (210–220)` ❌
- `largest_room`: `Answer: Seminar room 0.32, 61.4 m²`. The right room's name or number must appear **before** any other room, plus the area within ±5%.
- `room_stacked`: `Answer: Office 1.29`. Right room before any other room name.
- Counts exact. Distances ±1% (at least ±1 m). Areas ±5%. 3D distances ±2%.
- Every one of the 145 ids must have a row. An empty row is a wrong answer.

### The Sunday building
Shortly before code freeze on Sunday the organizers publish one new building nobody has seen, in the same
format, plus a question file. We run **one command** on it (documented in `BENCHMARK.md`), with no manual
steps, and submit the output. They may re-run our command to check. Anything hard-coded to the practice
buildings fails there. The command gets rehearsed on Saturday.

### The data format in 60 seconds (`building.json`)
```
building              id, name, source
floors[]              id, level (0 = ground, -1 = basement), name, elevation_m, height_m
spaces[]              id, floor_id, type (room|corridor|stair|lift|hall|outdoor), room_type (office, lab, ...),
                      name ("Office 1.12"), ref ("1.12"), polygon [[x,y],...] in metres, y up
openings[]            id, floor_id, space_ids [a, b] ("outside" = entrance), kind (door|opening|entrance),
                      position [x,y], width_m, step_free
vertical_connectors[] id, kind (stairs|lift), name, floor_ids[], space_ids[] (one stop space per floor), step_free
assets[]              id, name ("Desk 2.03-B"), category, type ("cnc_mill"), space_id, floor_id, position, footprint
```
Route model (already in `starter_agent/building_map.py`): one node per space at `Polygon.representative_point()`,
one node per door at its position, edges space↔door by straight-line distance, stairs 12 m per floor, lift
15 m + 6 m per floor, all entrances meet at one `outside` node. Step-free routing drops every `step_free: false` edge.

## 4. Contracts (change only after telling the whole team)

### 4.1 Core → Agent: Python API in `core/building.py`
`class Building(starter_agent.building_map.BuildingMap)`. Every method returns plain dicts/lists (JSON-able).
Every method accepts human references: a space id, an asset id, an exact name (`"Office 1.12"`), a ref
(`"1.12"`), or a unique substring. `floor` arguments accept an int level (`1`), a floor id, or words
(`"ground floor"`, `"Floor 2"`, `"Basement 1"`).

```python
Building.load(path)                                             # inherited
# lookups
b.resolve_space(ref) -> str                                     # id | name | ref | unique substring, else MapError listing candidates
b.resolve_floor(floor) -> str                                   # -> floor_id
b.room_types() -> list[str]
b.rooms(floor, room_type=None) -> list[dict]                    # {id, name, ref, type, room_type, area_m2}
# geometry
b.area_m2(space) -> float
b.largest_room(floor, room_type) -> dict                        # {space_id, name, ref, area_m2, runner_up: {name, area_m2}}
b.total_area(floor, room_type) -> dict                          # {total_m2, count, rooms: [{name, area_m2}]}
b.centroid_3d(space) -> dict                                    # {x, y, z}
b.straight_line_3d(a, b) -> dict                                # {distance_m, a: {...}, b: {...}}
b.shared_wall_rooms(space, min_len_m=1.0, tol_m=0.35) -> dict   # {count, rooms: [{name, shared_m}]}
b.stacked_room(space, direction) -> dict                        # direction "above"|"below"; {space_id, name, ref, overlap_m2, runner_up}
# graph
b.route(start, dest, step_free=False, via=None) -> RouteResult  # inherited
b.reachable_rooms(start, floor, step_free=True, min_width_m=None, closed=()) -> dict   # {count, rooms: [names]}
b.nearest_room_with_asset(start, asset_type, step_free=False) -> dict   # {space_id, name, distance_m, asset_id}
b.errand(start, asset_type, floor, room_type, step_free=False) -> dict  # {total_m, via: {...}, target: {...}, legs: [m, m]}
b.distance_to_exit(space, step_free=False) -> float
b.what_if_door(a, b, floor, threshold_m=1.0) -> dict            # {count, door: {...}, rooms_improved: [{name, before_m, after_m}]}
b.set_closed(ref, closed) / b.add_door(a, b)                    # inherited
b.route_geometry(route) -> dict                                 # {"floors": {"0": [[x,y],...], "1": [...]}, "length_m": ..}
```
Rules: no printing, no network, no state except `closed`. Each method covered by `core/oracle_check.py`.

### 4.2 Agent: entry point and benchmark command (what `BENCHMARK.md` documents)
```python
# agent/answer.py
def answer(building_directory: Path, question_text: str) -> str: ...
```
```
uv run --env-file .env python -m agent.benchmark <building_dir_or_split_dir> <questions.jsonl|questions.csv> --out answers.csv
```
Accepts one building folder or a whole split; questions as JSONL (`questions.jsonl`) or CSV
(`questions.csv` with `question_id,building_id,kind,question`). Parallel (4–6 workers), retries with backoff,
one failing question never stops the run (it still gets a row). Prints per-kind results when answers exist.
Also works through the kit: `python -m benchmark.evaluate data/dev --agent agent.answer:answer`.

### 4.3 Agent → Interface: HTTP API (`uv run uvicorn agent.server:app --reload --port 8000`)
```
GET  /buildings                      -> [{"id", "name", "source", "floors": [{"level", "name"}]}]
GET  /buildings/{id}                 -> the raw building.json (the UI draws polygons itself)
POST /buildings/{id}/chat            body {"session_id": "...", "message": "..."}
  -> {"reply": "...",                                   # what the user reads / hears
      "understood": "From Lobby 0.01 to Lab 1.07, step-free, Lift 1 closed" | null,
      "needs_clarification": false,
      "actions": [
        {"type": "route", "length_m": 123.4, "steps": ["..."], "floors": {"0": [[x,y],...], "1": [[x,y],...]}},
        {"type": "highlight", "space_ids": ["..."], "asset_ids": ["..."]},
        {"type": "closed", "element_ids": ["..."]},
        {"type": "door_added", "opening": {...}},
        {"type": "building_created", "building_id": "..."}
      ]}
POST /tts                             body {"text": "..."} -> audio/mpeg   (ElevenLabs; Sunday)
```
CORS open for `http://localhost:5173`. Interface works against `ui/mock/*.json` in exactly these shapes until CP2.

### 4.4 Builder → Core: Level 4 output
A `building.json` in the README §3 schema (section 1 above), one floor per `floors[]` entry, stairs and lifts
as `vertical_connectors`. Checked by:
```
uv run python -m builder.validate <generated.json> <truth_building_dir>      # IoU, refs, door pairs
uv run python -m core.validate_building <generated.json>                    # loads, connected, no overlaps
```
Agent tool signature (agreed at CP1): `build_building(name: str, image_paths: list[str]) -> {"building_id", "path", "report"}`.

### 5.2 Agent — "question in, Answer line out; and the conversation"

**Your goal**: a Claude agent that answers the 145 test questions in the exact scored format, runs on any
building with one command, talks well in a chat, and is reachable by the UI over HTTP. You also merge.

## 9. Glossary
- **Starter agent**: the organizers' working prototype in `starter_agent/`. Claude + six tools in a terminal. We extend it.
- **Agent**: Claude deciding what to do and which tools to call. **Tool**: a Python function Claude may call; its docstring is the instruction Claude reads.
- **System prompt**: the standing instructions Claude gets before the conversation. We have a benchmark one and a chat one.
- **`answer()` entry point**: the one function `answer(building_directory, question_text) -> str` the evaluator and the judges call.
- **Benchmark runner**: the script that runs every question through `answer()`, scores, and writes the CSV.
- **Oracle check**: calling our calculation functions directly with the known `inputs` from train/dev questions and comparing with the known answers. Free and fast.
- **shapely**: Python geometry library (areas, centroids, overlaps, distances between polygons).
- **SVG**: browser vector graphics; one `<polygon>` per room.
- **Claude vision**: sending an image to Claude together with text.
- **uv**: the Python package and environment manager the kit uses. **FastAPI/uvicorn**: the small web server. **Vite**: the web app dev server.
- **JSONL**: one JSON object per line. **Dev set**: buildings with answers for self-checking. **Test set**: buildings without answers that we submit.
